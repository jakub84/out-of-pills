# Repository Guidelines

Out of Pills is a web app where caregivers track how many pills are left per profile and when each medication runs out. Stack: Next.js 16 (App Router, TypeScript, Tailwind v4) on Vercel, with Supabase (Postgres + Auth) as the planned backend — see @context/foundation/tech-stack.md.

## Hard Rules

- Medication data is private to its caregiver. Every Supabase table gets Row Level Security enabled in the same migration that creates it, with policies scoped to `auth.uid()`. Never import the service-role key into code that can reach the browser.
- Access Supabase only through `@supabase/ssr` clients (one server, one browser helper); no direct `@supabase/supabase-js` clients in components.
- Server Components by default. Add `"use client"` only to files that use state, effects, or event handlers.
- The run-out date must never be later than the real one: round calculations toward the earlier date. Urgency colours: red ≤ 14 days, yellow ≤ 30, green above (@context/foundation/prd.md, Business Logic).
- Run-out maths lives only in `src/lib/medications/stock.ts`; change it test-first.
- Demo mode ("Try without signing in") never writes to Supabase.
- Commit `.env.example` only; never `.env` or `.env.local`.
- Do not run `npm audit fix --force` — it downgrades ESLint and eslint-config-next.
- Push migrations to the cloud project before merging the PR that adds them; never edit a pushed migration.
- Successful data changes (including future edit and delete) show a toast with text from `src/lib/feedback/messages.ts`, and their server actions run through `runSaveAction`; server and validation errors stay inline. In-app navigation that should show the loader uses `PendingLink` or `navigate`.

## Project Structure

- `src/app/` — App Router routes, layouts, `globals.css`. Import via the `@/*` alias (maps to `src/*`).
- `src/app/(app)/` — signed-in shell (header, profiles sidebar): `/` (selected profile via `?profile=<id>`) and `/profiles/new`.
- `src/app/onboarding/` — first-run steps (your name, first profile); `/` redirects here until both exist.
- `src/lib/profiles/` — caregivers and profiles: `dal.ts` (`getCaregiver()`, `listProfiles()`; inside `<Suspense>`), `actions.ts` (server actions), `validation.ts`.
- `src/lib/medications/` — medications: `stock.ts` (run-out calculation, Europe/Warsaw dates; unit-tested), `dal.ts` (`listMedications()`, `listAllMedications()`; inside `<Suspense>`), `actions.ts` (server actions: add a medication, add a package, correct the count; restock and correction apply only to the stock baseline the user was shown), `validation.ts`, `format.ts` (en-GB dates and tablet counts).
- `src/proxy.ts` — Next.js Proxy (formerly Middleware): refreshes the Supabase session and does optimistic auth redirects.
- `src/lib/supabase/` — `@supabase/ssr` helpers: `server.ts` (Server Components, Server Actions, Route Handlers) and `proxy.ts` (session refresh); the browser helper is added when first needed.
- `src/lib/supabase/database.types.ts` — generated by `npm run db:types`; don't edit by hand.
- `src/components/ui/` — shadcn components; change variants there, not at call sites.
- `src/components/brand/` (logo), `src/components/profiles/` (profile form with avatar picker, `ProfileAvatar` portrait-or-initial display, avatar colours and labels), `src/components/app-shell/` (header, sidebar with the running-out dot and account footer, user menu), `src/components/medications/` (add-medication dialog, overview tiles and cards, add-package dialog, card options menu with the correct-count dialog, urgency classes, header illustration that follows the most urgent medication).
- `src/components/navigation/` — `PageLoader` and `navigation-pending.tsx`: `useNavigationPending()` (`navigate`), `PendingLink`, `PendingRegion`, and `useSavedFormReset()` for forms that navigate away after saving.
- `src/lib/feedback/` — save feedback: `messages.ts` (toast wording), `run-save-action.ts` (error toast for failed requests; rethrows Next.js redirects).
- `src/app/auth/` — route handlers: `confirm` (email links) and `sign-out` (form POST, so signing out reloads the page and clears client state).
- `src/lib/auth/dal.ts` — `getCurrentUser()`, the authoritative signed-in check; call it inside `<Suspense>`, never in `use cache`.
- `supabase/` — local Supabase project: `config.toml` (auth policy), `templates/` (auth emails).
- `supabase/migrations/` — timestamped SQL migrations, additive only.
- `supabase/tests/database/` — pgTAP tests (RLS and privacy), run by `npx supabase test db`.
- `public/` — static assets; `public/avatars/` holds the profile portraits (`<avatar>.webp`, one per `PROFILE_AVATARS` value); `public/brand/stock-*.png` are the header illustrations.
- `context/foundation/` — living product docs: `prd.md` (requirements, FR-xxx ids), `tech-stack.md`. Edit in place.
- `context/changes/<change-id>/` — per-change research and plans. `context/archive/` is read-only.

## Commands

- `cp .env.example .env.local` — then fill in the publishable key from `npx supabase status`.
- `npx supabase start` / `npx supabase stop` — local Supabase stack (requires Docker Desktop running). API on http://127.0.0.1:55321, Studio on http://127.0.0.1:55323, Mailpit (auth emails) on http://127.0.0.1:55324.
- `npm run dev` — dev server on http://localhost:3000.
- `npm run build` — production build; must pass before a PR.
- `npm run lint` — ESLint; must pass before a PR.
- `npm test` — Vitest unit tests (`src/**/*.test.ts`); must pass before a PR.
- `npx supabase migration new <name>` — create a timestamped migration in `supabase/migrations/`.
- `npx supabase db reset` — rebuild the local database from all migrations.
- `npx supabase test db` — run the pgTAP tests in `supabase/tests/database/`.
- `npm run db:types` — regenerate `src/lib/supabase/database.types.ts` from the local database (stack must be running; check the file starts with `export type`).
- Migration release order: verify locally (`db reset`, `test db`, `db:types`) → `npx supabase db push --remote` (CLI 3 targets the local stack without `--remote`; `--dry-run` first) → check the PR preview → merge. Additive migrations only.

JavaScript unit tests run with Vitest (`npm test`, config in `vitest.config.ts`); database tests run with `npx supabase test db`. CI is `.github/workflows/ci.yml`: every PR runs `Lint and build` (lint, `npm test`, build) and gets a Vercel preview (URL commented on the PR); a merge to `master` deploys staging automatically, then production after approval in the `production` environment. Vercel deploys only from Actions (`vercel.json` disables Git deploys); Node is pinned by `engines.node` in `package.json`.

## Coding Style

- TypeScript `strict` (@tsconfig.json); no `any` without a comment explaining why.
- Lint rules: `next/core-web-vitals` + `next/typescript` (@eslint.config.mjs).
- Build UI from `src/components/ui` (shadcn) and the tokens in `globals.css`; no hex colours or `zinc-*` utilities in components.
- Style with Tailwind utility classes; Tailwind is wired through Turbopack in @next.config.ts, which also enables `cacheComponents`.
- Reference PRD requirement ids (e.g. `FR-014`) in plans and PR descriptions.

## Commits & Pull Requests

- Commit subjects: imperative, sentence case, no type prefix (e.g. `Add tech stack selection: Next.js + Supabase on Vercel`).
- Branches: `<area>/<slug>` (e.g. `setup/init-app`); open PRs against `master`.
- `master` accepts changes only through a PR with a green `Lint and build` check (don't rename that job). Production deploys need a manual approval in GitHub Actions.
